# 与生产环境的差异和当前限制

当前工程展示“领域理解 → 模板优先 / ReAct 扩展 → 白名单工具 → 结构化证据 → 回答”的可运行骨架。已有三种时间意图、4 个文字场景、18 个工具、预算和持久化；这些是已实现能力，不应再按旧版描述成仅支持三类问题和少量月份字符串。

## 指标和业务口径

全店基础指标为销售额、去重订单数、AOV；另有销售贡献、品类销售、流量转化、活动、价格、缺货等工具。指标标识在任务中开放，不代表工具支持所有指标。

当前缺少 SKU/品类订单数和 AOV、毛利与退款、复购/用户分层、库存可售天数、完整 SKU 明细遍历、预测等。Top10 贡献榜不是完整下降列表；活动带标记订单金额不是增量 ROI；同品类销售变化不是需求转移证明；原始缺货流水不是可靠缺货时长或因果损失。

现有因子 MD 会被当作业务说明加载，其中“影响/替代”等解释需受真实工具口径限制。结构、数字和实体检查不能完全拦截深层因果断言；不能把演示提示词等同于生产归因模型。

## 时间和数据就绪

支持 day/week/month/quarter/year 自然周期、最近 N 日、绝对日期；默认只到昨日，保存冻结时间。当前没有实时/小时分析、自动同比策略、交易日/节假日可比或多数据源独立水位。

BUSINESS_DATA_THROUGH 为配置水位，不会自动检测实际数仓齐备程度；历史时间在上界内也不保证数据完整。旧记录缺少冻结上下文时不能补回原参考日。种子数据只在空库初始化，不持续更新。

## 工具规模和语义校验

按需加载完整 Schema 已实现，模型初始仍接收全量轻量摘要。当前是 18 个工具，没有 50 个真实工具或相关规模效果测量。没有向量工具检索和完整 JSON Schema 引擎。

参数引用、输入/输出形状、指标/范围标签、时间和部分实体匹配能降低错误，但没有统一币种、单位、可加性、口径版本、因果假设与跨市场数据覆盖证明。SQLite REAL 和业务 double 精度仍存在，不是全链路高精度数仓。

## 权限和租户

merchantId/userId 用于会话组织；当前没有完整登录鉴权、角色/指标权限、商家行级 SQL 隔离、字段脱敏或跨租户访问保护。sessionId/runId/轨迹接口也没有完善的授权边界，不应直接部署成公开多租户服务。

轨迹可能保存完整 prompt、输入和业务结果，需生产保留与访问策略；API key 不是业务事件内容，但这不等于已有完整敏感信息治理。

## 执行和可靠性

API 同步；SQLite 本地落库。固定 DAG 有层内并发，ReAct 有单调用超时、次数、无进展、重复错误和提示长度预算，恢复不会重置预算。

尚无多实例分布式锁、后台异步任务、跨 run 查询缓存、Exactly-once、副作用工具事务、供应商成本结算控制或完整外部取消保证。ReAct 的 90 秒是本分支预算，不是整个 HTTP API 的硬超时 SLA；前置理解和不可抢占阶段另有边界。Playbook 没有同等的统一动态运行预算。

## 质量与评测

已有自动化路由、时间、计算、工具、HTTP、超时、恢复和证据测试。当前 intent 评测仍按旧的 scene/metric/time/entity/factor 字段计分，尚未完整评测 routing、requirements、改写保真、场景选择和 ReAct 逐项完成度。

在线 ReAct 回答采用数字和实体 grounding，不是所有业务语义硬校验；机械检查无法完整理解因果和每句建议。旧版本真实模型实验保留在[评测文档](eval.md)，不能作为本轮混合架构的效果证明。仍需新的真实模型多场景验收、成本/延迟统计和持续 bad case 回流。

## 需要扩展时

先分清缺口：缺数据/指标就补工具和口径；路线稳定就补 Playbook；可文字指导的组合任务就补场景；已有工具但模型执行差就改决策协议与评测。仅增加 ReAct 轮数或一句 guidance 不能弥补数据缺失。
