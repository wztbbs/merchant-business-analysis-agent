# 与真实生产环境的差异

这个开源工程抽象自真实商家经营分析项目，但为了便于公开、部署和理解，去掉了公司内部的数据口径、业务规则、权限体系和工程依赖，只保留核心分析链路：意图识别 → 固定模板生成计划 → 执行数据查询 → 生成可追溯结论。

因此，开源版本重点展示的是「如何用固定分析流程约束 LLM，保证经营分析结果可控、可查、可复现」，而不是完整复刻生产环境的全部复杂度。真实环境中还会有以下差异：

1. **指标层复杂度更高**

   开源版本只保留了 `sales_amount`、`order_count`、`aov` 三个演示指标，时间口径也只覆盖上月、前月、当月等少量场景。

   真实环境中的指标体系要复杂得多，通常需要支持：

   - 更多业务指标，例如 GMV、实付金额、毛利、退款、曝光、访问、转化、复购、履约、库存、活动补贴等；
   - 更多分析维度，例如门店、城市、区域、品类、品牌、SKU、渠道、活动、用户类型等；
   - 更多时间口径，例如日、周、月、自然月、滚动周期、自定义时间段；
   - 更多对比方式，例如环比、同比、YoY、WoW、MoM、活动前后对比、同周期对比；
   - 单店、多店、区域汇总、集团汇总等不同经营主体；
   - 不同指标之间的口径依赖、可加性差异和权限边界。

   因此在生产环境里，指标层通常需要单独建设，包括指标定义、维度定义、时间解析、对比基准、聚合规则、过滤条件、权限约束和 SQL / OLAP 查询适配。

2. **场景和原因模块更多**

   开源版本只实现了三类场景：

   - 指标变化诊断；
   - 因子影响评估；
   - 指标查询报表。

   真实环境中通常还会继续扩展更多场景，例如：

   - 活动复盘；
   - 商品机会诊断；
   - 门店对比分析；
   - 履约异常分析；
   - 库存健康分析；
   - 价格竞争力分析；
   - 广告投放效果分析；
   - 新品表现分析；
   - 经营日报 / 周报自动生成。

   对应的原因模块也会更多，并且不同业务线会有不同的数据可用性和判断规则。开源版本中的下架、活动、流量、价格、缺货模块只是为了展示模块化排查机制。

3. **数据源和查询引擎更复杂**

   开源版本使用 SQLite 和本地种子数据，便于一键启动和复现。

   真实环境中通常会对接多类数据源，例如数仓、实时 OLAP、指标平台、商品系统、活动系统、库存系统、流量系统、广告系统等。不同数据源之间可能存在延迟、口径差异、主键不一致、明细缺失等问题，需要在数据接入层做额外治理。

4. **权限、租户隔离和审计要求更严格**

   开源版本只做了基础的 `merchantId + userId` 会话隔离说明，没有实现完整权限控制。

   真实环境中通常需要处理：

   - 商家、门店、区域、角色等多级权限；
   - 不同用户可查询的指标和维度范围；
   - 敏感字段脱敏；
   - 查询审计和操作留痕；
   - 跨店、多店聚合时的数据授权问题。

5. **结论质量控制更严格**

   开源版本已经提供了意图识别评测和 grounding 校验，用来约束 LLM 输出不要编造数字。

   真实环境中通常还会增加更多质量控制手段，例如：

   - 结论打分；
   - 归因可信度评分；
   - 低置信度结果降级展示；
   - 异常数据识别；
   - 重要数字强制引用来源；
   - 不同场景的人工验收集；
   - 线上 bad case 回流和持续评测。

6. **生产环境通常还需要异步任务、缓存、监控和灰度发布**

   开源版本为了演示方便，接口是同步返回，并且使用本地数据库保存运行记录。

   真实环境中通常会进一步平台化，例如：

   - 异步任务执行；
   - 分布式任务调度；
   - 查询缓存；
   - 结果版本管理；
   - 多模型路由；
   - prompt 版本管理；
   - 灰度发布；
   - 监控告警；
   - 成本和耗时控制。

7. **开源版本的定位**

   这个工程的目标不是复刻公司内部完整系统，而是用一个可运行、可测试、可追溯的最小实现，展示经营分析 Agent 的核心设计：

   - 不让 LLM 临时决定查询路线；
   - 用场景模板和原因模块生成静态执行计划；
   - 执行计划在运行前可校验；
   - 查询能力白名单化；
   - 节点结果结构化落库；
   - 追问可以复用历史分析结果；
   - 最终结论必须基于查询结果生成。

   生产环境中的指标层、权限层、数据接入层和质量评估体系会更复杂，但核心链路仍是：模板生成计划、白名单查询、结构化落库、基于结果生成结论。
